# Service Quality Standard

## Principle
Do not sell hype. Every offer must be backed by a deliverable that looks and feels worth the price.

## Bar for every service

### 1. Specific outcome
Each service must promise a concrete business outcome:
- save time
- identify bottlenecks
- improve conversion
- generate qualified leads
- create reusable operating systems

Avoid vague claims like “AI transformation” unless tied to a workflow.

### 2. Professional deliverable
Every paid service must include:
- polished Google Doc/PDF report or structured Sheet
- executive summary
- prioritized recommendations
- implementation checklist
- next-step roadmap
- clear assumptions and limitations

### 3. Evidence-based diagnosis
Audits must cite observable evidence:
- website copy
- CTA placement
- offer clarity
- funnel gaps
- competitor references
- workflow steps
- lead quality assumptions

No generic AI fluff.

### 4. Scope control
Every offer must say what is included and excluded.

### 5. Upsell only after value
Implementation offer should follow a useful audit, not precede it.

## Minimum deliverables by service

### AI Business Audit
- 8–12 page report
- 5-dimension scorecard
- top 3 bottlenecks
- rewritten positioning/CTA suggestions
- 7-day implementation plan
- optional 30-day roadmap

### Website Conversion Audit
- page-by-page teardown
- hero rewrite
- CTA rewrite
- trust/proof recommendations
- friction list
- priority implementation plan

### Sales Ops / Lead Gen Tracker
Must look like a real operating dashboard, not a toy sheet:
- dashboard summary
- prospect scoring
- pipeline stages
- outreach cadence
- reply tracking
- deal forecast
- revenue tracking
- data validation/dropdowns
- formulas
- sample data
- instructions tab

### Lead List + Outreach Pack
- defined ICP
- lead source notes
- fit score
- personalization reason
- first-line opener
- suggested offer angle
- QA notes

### AI Automation Audit
- workflow map
- automation opportunities
- tool stack
- ROI/time saved estimate
- implementation complexity
- risks/access needed
- first automation blueprint

## Language standard
Use confident but grounded language:
- “I will identify…” not “I guarantee revenue”
- “designed to improve…” not “will 10x”
- “practical AI systems” not “revolutionary AI”

## Rule
If the portfolio example looks weak, do not show it. Upgrade it or remove it.
